# Build Decisions

Appended by build agents when the spec is silent. Format: `- [phase.task] decision — why`

- [plan] Radio nav item links externally to the SMFM site (URL from Header options `radio_url`, default https://radio.sistermidnight.org) — user chose defaults
- [plan] Venue and Support pages built as Page Header + Section blocks from patterns — undesigned
- [plan] News archive is a 2-column News Card grid — undesigned
- [plan] Paper texture skipped unless an asset exists in assets/static/images; CSS hook `body::before` left in place — no exported asset
- [plan] Hero built with poster image; video slot empty until a file is provided
- [plan] Seed script creates a plain GF newsletter form (email + submit); Brevo add-on mapping configured by hand later
- [plan] burnt-sienna/warm-sand used for body text only if contrast ≥ 4.5:1; otherwise limited to ≥ 24px or bold ≥ 19px text
- [0.0] Originals kept at assets/fonts-source/*.orig.woff2 instead of inside assets/static/fonts — Vite publishes all of assets/static, so that is the only way to keep them out of public/; files are small (~15KB) so they stay in git
- [0.1] No `paper-light` colour added; `cool-grey` (#DADAD9) stands in for Figma #E8E5E1 — close enough per spec, one fewer token
- [0.1] `type-body` added as an alias of `type-base` — spec names `type-body`, theme already used `type-base`; both now work
- [0.1] Focus ring is `2px solid var(--color-foreground)` with 3px offset, root `--focus--color` now follows the colour context (warm-sand on dark, dark-umber on light) instead of the accent — matches the spec's warm-sand/dark-umber outline
- [0.1] Paper texture not implemented (no asset exported); hook left commented on `body::after` in `2-base/_base.pcss` because `body::before` is already the backdrop overlay
- [0.1] Layout helper is `content-layout` (two halves, `--container-content: 1237px`, gap 20–40, `__media` / `__text` children, `--reverse` modifier); media half hidden below md unless `__media--always` — spec says illustrations hide below md
- [0.2] Illustration `size` is an optional modifier (`sm` 120–200, `md` 240–400, `lg` 320–562 via spaceFluid); no size fills the container width — spec says "size via CSS", the design frame uses 562px; sizes exposed as `--illustration--size` so callers can override
- [0.2] SVGO run with `convertColors currentColor` and `removeDimensions`; the fixed `#c4b29f` (warm-sand) fill is now `currentColor` and the SVGs scale from `viewBox` — needed for the spec's currentColor rule
- [0.3] Base `.button` stays unstyled (only a reset + focus ring); the design lives on `button--primary` / `button--link` modifiers — the accordion and sub-menu togglers already use `Button::make` as a plain control and must not pick up the fill
- [0.3] `Button::make` gains `variant`, `url`, `target`, `arrow`; with `url` it renders an `<a>` (rel="noopener" for `_blank`) — the design's buttons are mostly links (tickets, map), and a single component keeps the markup identical
- [0.3] One right-arrow inline SVG serves both variants (no separate ↗ for external links) — spec names a single "arrow icon"; primary uses `space-between` so the arrow sits at the right edge like the Figma 200×58 frame
- [fix-foundations] Primary button focus ring is inset (`--base--focus-offset: -4px`) so it is drawn warm-sand on the burnt-sienna fill (3.5:1) rather than outside the button on the section colour, where it was ~1.1:1 on stone-beige
- [1.1] Event field group saved at theme `acf-json/group_event.json` (not `Theme/Modules/Events/acf-json`) — that is ACF's save path, so admin edits round-trip to the same file; the module's extra load path is left in place
- [1.1] `end()` treats an end time earlier than the start as next-day (e.g. 20:00 – 02:00) — spec gives no rule; events running past midnight are the common case
- [1.1] `ticket_type` defaults to `buy`; unknown/empty values are treated as `buy` so a missing field never hides a ticket link
- [1.1] Location taxonomy switched to non-hierarchical to match the spec's "Hierarchical: no" (no terms exist yet, so nothing is lost)
- [1.2] Radio fields live in a new `group_radio` on the Header options page and Newsletter fields in `group_newsletter` on General; `radio_url` and `membership_link` sit in `group_header` — no new option pages, the radio bar is part of the header and the newsletter banner is site-wide
- [1.2] "Primary"/"Footer" menus are the existing nav menu locations (`header`, `footer-1`, relabelled; unused `footer-2` removed), not ACF fields — keeps menus editable in Appearance > Menus where they are already assigned
- [1.2] Existing `footer_legal_text` serves as `legal_text`, and old footer fields (`footer_text_*`, `footer_images`, `header_call_to_action_1`) are kept until the footer/header rebuild — removing them now would break the current templates
- [1.2] `hero_illustration` / `newsletter_illustration` select choices are loaded from `Illustration::NAMES` via `acf/load_field` — one source of truth for illustration names
- [1.2] `listen_url` left empty by default; consumers fall back to `https://stream.radio.co/{station_id}/listen` — spec gives no default and the stream URL derives from the station
- [1.3] Seed uses core `post` for news (not the `article` CPT) per spec; existing Primary/Footer menus are emptied and rebuilt, existing pages reused by slug; Gravity Forms is not installed so newsletter_form_id is a placeholder 1 and the GF form must be created when the plugin is added.
- [1.4] Feed changes only mark it stale; one rebuild runs at `shutdown` — a single save fires `save_post_event` and `set_object_terms` several times, so this keeps it to one query and one file write per request
- [1.4] `start` and `end_time` are ISO 8601 with offset (`end_time` null when unset, already rolled past midnight); `timezone` is `wp_timezone_string()`; `poster` is the featured image at `medium_large` or null — spec names the keys only; ISO with offset lets the client do today/past maths without its own timezone table
- [1.4] `sm/v1/events?before=YYYY-MM` returns the 3 months before that month (exclusive) in the feed's shape; transient key includes the feed's `generated` so a rebuild invalidates old chunks — same chunk size as the feed's past window, one request per 3 months of back-navigation
- [1.4] Long cache headers for `feed.json` are left to the web server (static file in uploads); the `?v=generated` query from `Feed::url()` busts it — the theme cannot set headers on a static file
- [1.5] Status endpoint is fetched first and the track endpoint only while online; the result (including offline/failure) shares one 30s transient used by both the server render and `sm/v1/now-playing` (sent with `Cache-Control: max-age=30`) — an offline or unreachable station costs one request per 30s, never two
- [1.5] `title` prefers the track's `track_title`, falling back to splitting its `title` (or the status `current_track.title`) on " - " into artist/title; `radio_enabled` unchecked returns the offline state with no fetch — shows are often a single combined string
- [2.1] Header is static (in flow), not sticky/scroll-hiding; the old `--site-header--height` root var is gone (consumers fall back to 0) — spec describes no sticky behaviour, simplest option
- [2.1] Mobile breakpoint is `md` (768) and the nav is rendered twice (inline nav + inside the `<dialog>`), each `<nav aria-label="Primary">`; only one is ever displayed. MenuItem ids now get a `wp_unique_id` suffix so both renders are valid HTML — avoids JS moving nodes
- [2.1] Header padding 24px (16 below md) with wordmark/nav top-aligned, not the 104px content gutter — Figma places the wordmark at 24,24 and the nav at y=23; wordmark is `type-h3` on both variants as the spec says (Figma's front page uses 60px)
- [2.1] Dialog buttons carry `command`/`commandfor` so they work without JS where invoker commands are supported; scripts.js only adds the click fallback, close-on-link-click and close when the viewport grows past `--site-header--breakpoint`
- [2.1] Burger and header-search components are no longer used by the header but left in place for the final cleanup phase; `variant` defaults to `hero` on `is_front_page()`
- [2.2] Hero renders outside `<main>` (between header and main in `front-page.php`) — it is decorative media with no content, so the skip link lands on the page content, and no `alignfull` plumbing is needed
- [2.2] The `<video>` has no `autoplay` attribute; `scripts.js` calls `play()` unless `prefers-reduced-motion: reduce`, `prefers-reduced-data: reduce` or `navigator.connection.saveData` — the poster is then what shows (also without JS), and the toggle (hidden until JS can drive it) still offers to play
- [2.2] Toggle semantics: `aria-pressed="true"` = paused, label "Pause video"; once the video has played the root gets `data-hero-started` so a paused video holds its frame instead of snapping back to the poster
- [2.2] Seeded a generated 1920×1080 placeholder poster and a 6s 300KB placeholder MP4 (both titled "placeholder") into Header options with illustration `dancers`; the old `theme/homepage-hero` block was stripped from the Home page content (the Hero partial replaces it) and the `homepage-hero` component is left for the cleanup phase
- [2.3] No SMFM marque/wordmark SVG exists in the theme, so the marque is a simple drawn inline SVG (record with a quarter arc) and the wordmark is "Sister Midnight FM" as text in the display font (`type-h5`, uppercase) — swap in the real SVG when the asset is supplied
- [2.3] When the station is offline the bar still renders (brand + Listen) and only the "Now playing" line is hidden — the spec's "hidden" is read as the track text, so the 60s refresh can reveal it when the station comes back without a layout change; `radio_enabled` off removes the bar entirely
- [2.3] Radio Bar renders only on the front page (`front-page.php`, between Hero and `<main>`), matching the Front Page spec; the brand is plain text, not a link, since the SMFM site URL is not in the spec
- [2.3] `RadioService::isEnabled()` added so the component and the fetch share one `radio_enabled` check; the refresh pauses while the tab is hidden
- [2.4] Footer strip uses the existing `assets/static/images/dancing-footer.svg` (1383×316, the exact Figma "dancing" frame with disco ball and stars) inlined via `SVG::get` with `fill: currentColor`, not `illustrations/dancers.svg` (a square 800×800 group used by the Hero) — matches the design and takes the warm-sand foreground; as an `<img>` it draws black
- [2.4] Existing `footer_images` rows were copied into the new `supporters` repeater (name = link title, else image title); the old `footer_text_top`, `footer_text_bottom` and `footer_images` fields are removed from the Footer group (their option values stay in the DB untouched); `map_link` was empty so it is seeded with a Google Maps search for the address
- [2.4] `logo-grid` is not used by any content; the footer now owns supporter logos and the component directory is left for the cleanup phase, as the spec says to delete only then
- [2.4] Footer nav links and "Open map" are `type-small` (Figma shows four 14px rows), the address `type-body` (FOSS 21), the legal text `type-small`; social icons are 24px (Figma 18) so they meet the 24px touch target; horizontal padding is 24px (16 below md) like the header, since the Figma footer inner has p0/24/24/24
- [2.4] Supporter logos are flattened to a light silhouette with `filter: brightness(0) invert(1)` at 0.8 opacity (alt = supporter name, 40px high) — the Figma "Mask group" shows light logos and plain `grayscale(1)` leaves dark logos invisible on dark-umber; a CSS mask was tried first but mask images need CORS and this site's uploads are served from the staging domain locally; logos must have transparent backgrounds
- [2.5] No Gravity Form existed, so form 1 "Newsletter" was created with GFAPI (one required email field labelled "Email address", placeholder "email", hidden-label placement, honeypot and validation summary on, button "Sign up", message confirmation) and `newsletter_illustration` seeded with `trumpet` — the option already pointed at form 1
- [2.5] The submit control is swapped for the primary Button via `gform_submit_button` (scoped to the newsletter form id) so the arrow is an inline SVG; the gravity-forms `[type='submit']` restyle skips `.button` so the two don't fight
- [2.5] No page field group existed yet, so `acf-json/group_page.json` ("Page", side position) is created with `hide_newsletter`; later page fields (intro_text, header_media…) belong in the same group
- [2.5] The banner is rendered from `footer.php` (`NewsletterBanner::fromOptions()`, before the Site Footer) rather than per template: every template calls `get_footer()`, and `fromOptions()` returns null on the front page or when `hide_newsletter` is set, so no template needs to know about it
- [2.5] Banner is a `<section aria-labelledby>` with an `<h2>` styled `type-h3` — the spec lists `aside` for the radio bar only and the heading must sit in the page outline under the single `<h1>`
- [2.5] The old `newsletter-signup` component (custom REST endpoint + Brevo call) is removed as part of the refactor; the `Newsletter` module's REST endpoint and Brevo settings fields are left for the cleanup phase since the GF Brevo add-on now owns the list push
- [2.6] Page Header is now a pure partial: the old `theme/page-header` block (block.json + its field group), breadcrumbs, CTA and background options are removed — the spec lists it as a Partial and no content used the block
- [2.6] `PageHeader::fromObject()` resolves the queried object (page → its fields; search/404/archives → the router page's fields, falling back to a label and a default intro) so every template calls one method; `fromPage()` reads intro_text/header_media/header_illustration/header_image
- [2.6] The page field group moves from the sidebar to `acf_after_title` with a `header_media` select of none/illustration/image (default none) so the intro WYSIWYG sits under the title; illustration choices load via the same `acf/load_field` filter as the hero
- [2.6] Page header has no colour context of its own: it sits on the page background (dark-umber) as in the design; intro links take the foreground colour and an underline because burnt-sienna on dark-umber is ~1.9:1
- [2.6] Mobile: the label is a normal `type-h2` heading above the intro and the media follows the intro (illustration 60% wide, image full width), via `content-layout__media--always` plus `order`
- [2.6] 404: the not-found message is the header intro by default (the 404 router page can override it with its own intro_text or content), so the empty router page no longer prints an unstyled paragraph; search keeps the Template Content slot fallback so results render even when the page has no block
- [2.6] Seeded About (intro from the Figma copy, illustration `stars`) and the 404 router page (illustration `moon`); page content was left untouched
- [2.3-fix] SisterMidnight is declared at `font-weight: 700` (one heavy cut, so no synthesised bold) and `display-heading-attributes` uses the bold weight; the radio bar wordmark and Listen link are both `type-h5` pinned to 20px at every width — warm-sand on burnt-sienna is 3.47:1, which WCAG allows only for bold text >= 19px (the fluid h5 token drops to 18px on narrow screens, which axe rejects), and 24px+ text would overgrow the 64px bar
